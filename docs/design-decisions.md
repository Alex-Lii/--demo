# 设计决策记录 · 盏 ZHAN 家庭调酒 App

本文件记录「盏」从初版到定稿过程中，几次**改变了方向**的取舍：当时有哪些候选、为什么选这一个、为什么放弃另一些、留下了什么代价。
目的是让没有参与过程的人（或换台机器后的自己）只看仓库就能理解「为什么长这样」，而不需要翻聊天记录。

**读法**：每条决策按「背景 → 候选 → 选择 → 放弃的理由 → 代价」排列。结论很短，理由尽量写足。
**数值来源**：优先引用仓库内文件（`README.md`、`docs/cocktail-app-prd.md`、各版本 `styles.css` / `*.js` / `*.html`）。`mockups/v6/optimize-report.md` 与部分构建脚本只在源目录、未随归档入库，引用时已注明；少数只在设计评审时测过的数值标为「评审实测」。

## 1. 视觉基调：从浅色暖米纸转到深色 `#17181C`

**背景**：初版（`mockups/v1`、`mockups/hifi`）沿用「暖米纸 + 琥珀」的日间阅读感，理由是家庭场景、纸质食谱联想。

**候选**

| 候选 | 内容 |
|---|---|
| A 浅色暖米纸 | 米白底 + 琥珀强调，纸质食谱气质 |
| B 深色玻璃 | `#17181C` 中性深灰底 + 玻璃浮层 |
| C 严格品牌规范 | Anthropic 官方品牌体系：`#FAF9F5` 米白 + `#D97757` 陶土橙 + Poppins/Lora |

**选择**：B。`mockups/v3/styles.css` 起 `--bg:#17181C`，`mockups/v4` 微调为 `#1A1B20`（比定稿略亮的中性深灰，B 通道偏高、偏冷），定稿再回到 `#17181C`（更深、更中性，给玻璃留出层次余量）。

**为什么放弃 A**

1. **使用时段**：调酒发生在夜间/低光环境，浅色大面积发光面在暗环境里刺眼，也压不住氛围。
2. **素材全暗调**：配方图与酒款照片都是低照度、深背景的实拍。放在米白底上，图片边缘会形成硬切，整页像「贴图册」；深色底让照片自然融进背景。
3. **玻璃质感需要暗底**：`backdrop-filter` 的折射与高光在浅底上几乎不可见，B 方案的核心视觉手段直接失效。

**为什么放弃 C**（`mockups/v5-a` → 保留为 `mockups/v5-b`）

`mockups/v5-a/brand-a.css` 是严格照搬版：整站换成 `#FAF9F5` 米白 + `#D97757` 陶土橙，字体换 Poppins/Lora，`--glass-tint:transparent`（玻璃全让位）。跑完之后**否掉**，原因写在文件头：

- 品牌规范的原意是「文档/出版物的排版权威感」，不是「夜间消费类 App」；照搬后调酒场景的氛围消失，产品看起来像一份说明书。
- 陶土橙 `#D97757` 压在米白 `#FAF9F5` 上只有约 3.2:1，作为主强调色必须另派生一个更深的 `#B0522F` 才能做正文级文字——为了「守规范」反而要破坏规范。
- 换色等于推翻 `mockups/v4` 已定稿的全部 token 与钻石材质参数（玻璃、双极性边、等级色），收益与成本不成比例。

**实际保留的**：`mockups/v5-b/brand-b.css`，即「取纪律不取色」——只吸收排版纪律（6 级字阶 display 30 / h1 20 / h2 15 / body 13 / caption 11.5 / micro 10.5、全站只用 400/600 两档字重、负字距只给 ≥20px 标题、8pt 栅格、圆角收敛 8/12/20/32、强调色只用于可交互与状态），盏的琥珀、深色玻璃、等级色、DIY 角标全部保留。

**代价**

- 浅色体系没有被验证到可交付程度，`mockups/v1`、`hifi` 只作历史留档；若未来要做日间模式，需重新做一套浅色 token 与玻璃替代方案，不能简单反色。
- 深色底带来**对比度压力**：所有次级文字必须重新配比（见第 2 条），`#9598A2` 在 `#17181C` 上 6.16:1、在 `#232428` 内容层上 5.38:1（`optimize-report.md` 实测），低于这个值的灰一律不能用。
- 深色底是非 HIG 默认选择，属于**主动偏离**，理由记录在 `optimize-report.md` 第三张表。

## 2. 玻璃浓度的两轮收敛：从 tint .30 / blur 24 到 .20 / blur 20 + saturate 190%

**背景**：玻璃是这套设计的核心手段，但「多透」直接决定文字可读性，必须定量收敛，不能凭好看。

**候选**

| 轮次 | 参数 | 结果 |
|---|---|---|
| 第一轮 | tint `.30` / blur `24px` | 玻璃"厚"、压照片稳，但整页发闷，像磨砂塑料，照片透不出来 |
| 第二轮 | tint `.20` / blur `20px` / `saturate(190%)` | 传透感出现，照片的颜色能透上来 |
| 更透（未采用） | tint `.16` / blur `16px` | 压照片时 10–11px 次级小字掉到 AA 以下 |

**选择**：第二轮。仓库里现存的最早定稿值即 `mockups/v4/styles.css`：

```
--gb:20px;                              /* blur */
--gs:190%;                              /* saturate */
--glass-tint:rgba(48,46,53,.20);        /* 中性偏暖，更透 */
--glass-tint-strong:rgba(16,17,21,.36); /* 压照片时保可读 */
```

`mockups/v5-b` 只覆盖排版纪律（不碰底色与玻璃），玻璃与底色继续沿用 v4 的这组值；定稿 `app/styles.css` 里仍是 `--gb:20px` / `--gs:190%` / `--glass-tint:rgba(48,46,53,.20)`，未再变动。

> 注：第一轮的 tint `.30` / blur `24px` 只存在于过程稿，未入库，因此**无法从仓库复现那一版**；本文件记录结论与转折，可比对的起点是 v4 的 `.20 / 20 / 190%`。

**为什么停在 .20 / 20**

- **下限是文字定的，不是审美定的**。玻璃面板上压着 10–11px 的次级信息（酒款信息、帖子作者、时间戳）。透明度继续下探时，照片高光区透过面板，文字实际对比度跌破 4.5:1。
- 更透的方案只能靠「把字提亮」补偿，但提亮到某个点，次级文字就和主文字同级，信息层级塌掉。
- 实际做法是**分层处理**而不是一味降透明度：一层 `--glass-tint`（.20）给普通浮层，另一层 `--glass-tint-strong`（.36）专门用于「压照片」的场景，需要更强遮蔽时切到后者。

**代价**

- 玻璃只在**浮动 chrome** 上成立。`optimize-report.md` 2.1/6.1 记录：卡片、列表组、统计块原本全部 `.glass`，导致内容层与 chrome 不分层；定稿改为新增 `.surface`（白色 5% 填充 + 1px 顶部高光、无边框无投影），玻璃只保留 tabbar、ctabar、sheet、图标钮、压图角标等浮动层。**「玻璃质感」的覆盖面积比最初设想小很多。**
- `saturate(190%)` 会把照片里的高饱和色放大，个别酒款照片会偏色；目前接受，未做逐图校色。

## 3. 等级体系的三次重构：四色 → 钻石单色五档 → 四维风味驱动

**背景**：等级（难度）要在列表、详情、筛选里反复出现，既要一眼可读，又不能抢内容。

**第一代：L1–L4 四色兜底**（`mockups/v4/styles.css` 的 `--l1:`–`--l4:`）

- 做法：直接用酒款难度上色，`#7ED957` / `#F5A623` / `#D0021B` / `#1A1A1A`。
- 问题：**颜色本身承载了语义**，于是「红=难」和「红=危险/错误」冲突；而且 L1 的亮绿在深底上比 L4 的近黑醒目得多，视觉权重和难度顺序是反的。四色也与实际档位对不上——从 `icons-3d/v1` 起图标就是 **L1–L5 五档**（`L1.png`–`L5.png` + `@24`），只给四个色位必然有一档要和别人共用颜色。

**第二代：钻石单色五档**（`icons-3d/v1`–`v6`，`icons-3d/v5/rotating-icons.html`）

- 做法：一颗拉长方形双锥（八面体，8 个三角面 / 4 个可见刻面，无桌面、无腰围带），高宽比 1.34、冠 53% / 亭 47%（比例照参考图），五档只改本体色。提供两块色板：
  - **色板 A「宝石柜」**：五个不同色相——香槟金 `#DDB665` / 雾霾蓝 `#7BA7C7` / 墨绿 `#56926F` / 深酒红 `#BF455B` / 黑曜 `#655153`；
  - **色板 B「单色相」**：同一琥珀色系只走明度——香槟 `#DDA95B` / 浅茶 `#C28B47` / 古铜 `#A96E30` / 深褐 `#845923` / 黑曜 `#5B4A3A`。
- 为什么做两块板：A 更好看、更像「宝石」，但五个色相互相打架，用户会以为颜色代表不同品类；B 层级更清楚，但五颗石头长得几乎一样，失去"收集"的乐趣。
- 结果：两块板都没能同时解决「好看」和「不误导」。

**第三代：四维风味驱动不规则钻体**（`icons-3d/v10` → `v12`）

- 做法：把「难度」从钻石身上彻底剥离。钻石由配方的**四维风味**生成：
  - 甜度 → 整体高宽比（1.34 → 1.05）；
  - 酸度 → 冠高比（0.30–0.43）与台面半径（0.54–0.40）；
  - 酒精度 → 腰围偏心（−1…+1，横向 5%、尖端 5.5%、腰线倾斜 ±1.8%）；
  - 复杂度 → 由三轴分散度反量推导，控制亭部削面深度 6%–22%，第 4 刻面多一道切角。
  - 外形为 10 边环叠加双正弦扰动，相位由风味组合决定 → 同配方稳定复现、不同配方不重复。
- **颜色只编码风味身份**，不编码强弱：LCH 三锚点加权，酸 → 青柠 h≈105°、甜 → 蜜琥珀 h≈65°、酒 → 姜红 h≈36°，C* ≤ 56（`docs/cocktail-app-prd.md` 8.1）。
- **难度改走独立通道**：钻石旁用 caption 字号写阶名/数字（「二阶」「2」）；纯等级场景（筛选面板难度选项、酒款详情等级、酒库列表）**保留原琥珀色条与数字，不放钻石**——避免同一图形同时被读成「风味」和「难度」。

**为什么这样分**

把「是什么味道」交给形状与颜色（这是用户真正想知道的），把「几阶」交给文字与既有琥珀条（这是元数据）。一个图形只承担一个语义，才不会互相污染。

**代价（硬限制，不可回避）**

- **24px 下四维轮廓不可辨**。高宽比、冠高比、腰围偏心在这个尺寸被抹平，实际只剩色相与明度可读。也就是说：**小尺寸下它退化为一颗"有颜色的钻石"，四维信息只在 48px 以上才成立**。
- **成品钻只有 9 颗**。配方多于 9 条时按四维就近复用，长列表会出现可感知的观感重复，需在数据里标记复用来源（PRD 8.1 已知限制）。
- 第三代推翻了 `icons-3d/v10` 的"定稿"身份。v10 曾在 README 里被写成定稿，现在降为历史迭代——这是**明确的口径变更**，不是笔误。

## 4. 钻石材质：不透明 → 琉璃镜面 → 低多边形平涂 → 回到毛玻璃

**背景**：钻石要"值钱"，但也不能成为页面上最亮的东西。

**候选与失效点**

| 路线 | 做法 | 失效原因 |
|---|---|---|
| ① 完全不透明 | 纯色实体 + 面明暗 | 没有透光，像塑料积木；深色底上是一块色斑，读不出"宝石" |
| ② 琉璃镜面 | 靠**加法镀层壳**（外层再套一层高光壳）模拟镜面反射，非纯物理 | 不是物理正确的，转动时高光位置与面法线不一致，一动就"假"；且镀层让边缘发糊，24px 下轮廓被吃掉 |
| ③ 低多边形平涂（参考图路线） | `transmission 0.12 / thickness 0.28 / attenuationDistance 0.90 / roughness 0.58 / clearcoat 0.16 / dispersion 0 / flatShading`（`icons-3d/v5/rotating-icons.html` 标注为「参考版」） | 平涂切面清楚、24px 也稳，但整体像一张插画，与 v4 的玻璃体系割裂；`flatShading` 让材质失去透光层次 |
| ④ 毛玻璃（定稿） | `transmission 0.78 / roughness 0.30 / thickness 0.30 / clearcoat 0.50`（PRD 8.1） | — |

**为什么回到毛玻璃**

- 它是**唯一与页面玻璃体系同源**的材质：钻石和它所在的浮层是同一套透光逻辑，视觉上"长在一起"。
- 透光让深色底能透过宝石，宝石不再是贴上去的色块。

**代价**

- **`attenuationDistance` 超过 1.05，色相先死**：衰减距离拉长后，透射光被吸收到接近中性，酸/甜/酒三锚点的色相差被抹平，9 颗石头变成同一颗灰石头。因此 `attenuationDistance` 被限制在 1.05 以内，代价是**透光的"深度感"有限**，不能靠拉长衰减距离做厚重感（评审实测，本轮记录首次入库）。
- **折射依赖底片内容**：`transmission` 需要背后有可折射的东西才看得出来；纯色底上钻石会"化开"成半透明色块。静态 PNG 没有动画，立体感只能靠 `rotating-icons-v10.html` 这类实时渲染页表达。
- 路线②的「加法镀层壳」是**非物理取巧**，已被废弃；如果后续有人想"把高光做亮一点"，不要再回到这条路。

## 5. 钻石去描边：删掉外描边与接触阴影，代价是必须落托板

**背景**：v11 之前，为了让宝石在任意底色上都"有边"，给钻石加了 1px 双极性描边（深底亮边、浅底暗边）+ 接触阴影。

**候选**

| 候选 | 做法 |
|---|---|
| A 保留双极性描边 | 1px 内外双边 + `drop-shadow` 接触阴影 |
| B 完全去边 | 删除描边与阴影，只靠面明暗与棱线切面 |
| C 去边 + 实底托板（定稿） | B 的基础上，所有无边钻必须放在实底托板上 |

**为什么放弃 A**

- 深色托板上的**黑边只有 1.68:1**，等于没边；不仅没帮上忙，还多了一圈脏边，24px 下更像糊掉。
- 描边是"补丁"：它同时在解决「对比度」和「立体感」两个不同问题，结果两个都没解决好——边一加，切面层次被压平。
- `icons-3d/v12/stroke-ab-v12.png` 是有/无描边的 A/B 对照图；构建脚本 `build_v12.js` 里 `stroke=1` 只用来生成这张对照，成品不含描边。

**为什么 C 可行**

去掉描边后，对比度问题**从"加边"转成"换底"**：给钻石一个实底托板，用托板与钻石的明度差建立边界，比在钻石身上画边干净得多。

**代价：三条硬约束（不可协商）**

1. **无边钻必须放在实底托板上**。默认托板 `rgba(12,13,17,.84)` + 12px 圆角。
2. **深色底必须加深托板**：`.84` 的托板叠在 `#17181C` 内容层上只有 **1.08:1**，托板会"消失"（等于没有托板）。深色场景必须提到 `rgba(0,0,0,.94)`，或加 1px 内侧高光。
3. **脱板直贴白底不可行**：24px 无边钻直贴白底仅 **2.83:1**（PRD 8.1）。任何"把钻石直接放在卡片上更清爽"的想法都要先过这一关。

**附带的代价**：托板占用了 layout 空间，钻石不能"融"进照片；等于用**排版**换**可读性**。这是有意接受的——可读性优先。

## 6. 多倍率资产：24/48/72 各自超采样出图，禁止从大图缩放

**背景**：宝石是细碎切面，缩放算法会把高光糊成一片，24px 尤其明显。

**候选**

| 候选 | 做法 | 结果 |
|---|---|---|
| A 只有 1024，前端 `width:24px` 缩 | 一张图走天下 | 24px 下切面全糊，高光变成灰点；浏览器降采样不可控 |
| B 只有一张 24px，高清处拉伸 | 保证小尺寸 | 48/72px 处发虚，Retina 屏更明显 |
| C 逐档渲染 + 6× 超采样 | 每档按目标尺寸×6 渲染再精确降采样 | 定稿 |

**选择**：C。实现见 `difficulty-3d-v12/_src/build_v12.js`：

```js
const SS = 6;   // 小尺寸 6× 超采样
for (const px of [24, 48, 72]) {
  const size = px * SS;      // 144 / 288 / 432
  await shoot(b, `${base}&size=${size}&px=${px}`, size, `icon_${r.id}_${px}.png`);
}
```

界面侧（`app/app.js`）用 `srcset` 取档、`src` 指 1x 兜底：

```js
return `${p}/1x/flavor_${id}.png 1x, ${p}/2x/flavor_${id}.png 2x, ${p}/3x/flavor_${id}.png 3x`;
```

**为什么必须逐档渲染**

6× 超采样后再降到目标尺寸，等于用 36 倍的采样点做平均，切面边缘的高光不会跳变；而"1024 直接缩到 24"是 42 倍降采样，任何算法都会丢掉棱线。**这不是优化项，是正确性问题。**

**代价**

- 资产体积 ×3（每颗 3 档 + 1024），且**换一次材质要重跑全部 9×4 张**。
- 渲染依赖 puppeteer + 本机 Chrome，`build_v12.js` 里写死了绝对路径；`_src` 未入库，**本仓库无法直接复现出图**。
- 新增配置项时容易漏档：只补 2x 不补 3x 不会报错，只会在 3x 屏上糊。

## 7. HIG 优化轮：改了什么，以及刻意不改的四项

**背景**：视觉定稿后跑了一轮 iOS HIG 对齐（原始记录 `mockups-v6/optimize-report.md`，未随 v6 归档入库；方法为逐页实测 + Puppeteer 尺寸审计 + 对比度计算）。原则是**保留 V4 深色玻璃基底、钻石与信息架构，不换主题、不推倒重来**。

**改了的（摘要）**

| 项 | 问题 | 改法 |
|---|---|---|
| 筛选 sheet | 悬空 8px、四角全圆、被 tab bar 压住、CTA 露不出来 | 贴底、全宽、仅上方 28px 圆角、36×5 抓手；打开时隐藏 tab bar；底色加深到 86% |
| 搜索页 | 内容起点 48px，被 54–98px 的 navbar 压住，返回键压输入框 | 起点改 **110px**（54 状态栏 + 44 导航栏 + 12 间距）；输入框 44pt；去 Chrome 默认蓝框 |
| 触达 | 图标钮 40、seg 38、feed tab 26 宽、chip 26/32、勾选行 ~20 | 全部补到 ≥44×44；chip 用透明伪元素扩热区，视觉高度不变 |
| 层级 | 卡片/列表/统计块全上玻璃，内容层与 chrome 不分 | 新增 `.surface`（5% 白 + 顶部 hairline，无边框无投影）；玻璃只留浮动 chrome |
| 字阶 | 散落 9.5/10/10.5/11/11.5/12/12.5/13/14.5 | 收敛为 30/22/15/13/11.5 五档；`9.5` 一律提到 11–11.5，仅角标与步骤圆点保留 10 |
| 对比度 | 实色琥珀 CTA 白字仅 3.67:1；统计卡小字 ~3.0 | CTA 压深到 `#996738→#7A4F28`（4.83–7.06:1）；统计卡同上（≥4.7） |
| 语义 | 图标钮无无障碍名；tab 无当前页；`<button>` 嵌套 `<button>` | 补 `aria-label` / `aria-current` / `aria-modal`；外层改 `div` |

**刻意保留、与 HIG 冲突的四处**（`optimize-report.md` 第三节）

| 冲突点 | HIG 取向 | 我们的取向 | 理由 |
|---|---|---|---|
| 深色底 | 系统默认浅色/分组背景 | 固定 `#17181C` 深色玻璃 | 产品定位是夜间/酒吧场景，深色让酒色照片突出；改浅色会推翻整套 token 与钻石材质，收益低 |
| 浮动胶囊 tab bar 64 高 | 49pt + 安全区 | 浮动 64、tab 48 | V4 已定稿的 Liquid Glass 基线；48 已接近 49，选中只改 tint 不改形状，语义仍对齐系统 |
| 酒名衬线 | SF Pro 统一 | Georgia/宋体，仅酒名 | 品牌识别所需；范围严格限制在酒名，正文仍系统无衬线 |
| 徽标/圆点 10px | 正文不小于 11 | 角标数字、步骤序号 10 | 非阅读文本，有图形/数字冗余；HIG 对 tab 标签也允许 10 |

**代价**

- **Dynamic Type 未支持**（`optimize-report.md` 4.2）：全站 px 字号，不随系统字号缩放。未改是因为会牵动所有内联字号与卡片高度；已留的余量是标题单行省略、CTA 自适应宽、列表行固定 48/50。
- **Sheet 无拖拽关闭**：静态稿没有手势运行时，避免"看起来能拖但拖不动"，只支持遮罩与关闭按钮。
- **照片上的文字仍不保证达标**：透明度已提到 .88–.90，但任意照片的最亮区仍可能低于 4.5:1；真实实现建议加 20–40% 底部 scrim（当前 only hero 有渐变）。
- 这一轮只覆盖 App 路由；`levels` 规格页不在审计范围（它是对外规格文档）。

## 8. 标识可读性：照片上的钻石改「加托板」，不改「提亮文字」

**背景**：UI 里同时放着照片和风味钻石，两者都是中间调时，边界消失。

**候选**

| 候选 | 做法 | 结果 |
|---|---|---|
| A 提亮文字/加发光 | 给标签文字加亮、加 `text-shadow` | 治的是文字，不是钻石；钻石本身仍与照片糊在一起 |
| B 加深照片遮罩 | 整体压暗照片 | 牺牲素材，所有照片都变闷 |
| C 加实底托板 | 钻石坐在一块实色托板上 | 定稿 |

**为什么选 C**

钻石与照片的体色对比最低到 **1.02:1**（评审实测，近同色）。这个量级靠"更亮的字"救不回来——问题在钻石与底的关系，不在文字。加一块实底托板，等于在两者之间插一层已知明度的隔离带，对比度立刻变成可控量：**加托板后 5.4–7.2:1**（评审实测）。

**代价**

- 托板是**强制的**，不是可选装饰；`v12` 的所有用法都必须带托板，这直接限制了"钻石悬浮在照片上"这类排版自由。
- 托板颜色必须随底色变：浅底 `.84` 可用，`#17181C` 上必须 `.94` 或加 1px 内侧高光（`.84` 叠深底只有 1.08:1）。**换底图必须重新回归**。
- 照片底体色对比实测仅 **1.01–1.44**（PRD 8.1），意味着无论怎么调，照片上都不存在"裸钻"的可行方案。
