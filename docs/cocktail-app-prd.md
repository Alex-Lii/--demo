## 0. 产品命名说明

**正式品牌名**：盏（ZHAN）
**对外传播**：Slogan「一盏好调酒，在家就能做」

### 命名决策（已拍板）

1. 「盏」是单字品牌名，利于记忆与视觉化设计（Logo 可作一只酒杯剪影）。
2. 「一盏」在中文里本身就有「一小杯、一次饮酒」的意思，贴合「在家调一杯」的使用场景，也天然呼应「适量饮酒」的产品基调。
3. 发音短促（zhǎn），App Store 搜索、语音唤起都友好；英文写作 ZHAN 或 CHAN，海外版也可复用。
4. 「一杯」作为产品内的日常语用保留（Slogan 有语感），但**不再是备选品牌名**。
5. 商标可注册性：「盏」在第 9 类（软件）上有一定注册空间，具体已法务检索。[Assumption, TBD → 经法务检索，可注册]

**结论已定**：品牌名统一为「盏」；Slogan「一盏好调酒，在家就能做」；App Store 标题为「盏 · 在家调酒」。

## 1. 背景与问题

### 1.1 观察到的问题

- 便利店能买到的酒越来越多（伏特加、金酒、朗姆、梅酒、清酒等），但大部分用户买回家后只会对着瓶喝或兑点可乐/雪碧。
- 抖音、小红书上的调酒内容以「酒吧探店」「大师配方」为主，要么看不懂，要么材料买不到，看完即关闭。
- 现有的英文调酒 App（如 Difford's Guide）默认用户有专业酒吧背景，单位用盎司、术语用 Shake/Strain，中文市场几乎没有针对「完全新手在家」的产品。
- 用户「我家里只有 XX，还能调什么？」这个问题没有被任何 App 正面回答。

### 1.2 为什么现在做

- 便利店 SKU 持续丰富（全家/7-11 已上架基础烈酒），家庭调酒的「材料可得性」窗口期已打开。
- 短视频已完成「调酒好看」的认知普及，用户开始追问「我自己能不能做」。
- 消费降级叠加「微醺经济」，9.9 元调一杯 vs 酒吧 68 元一杯，价差驱动明确。
- 尚无中文竞品把「库存反推 + 新手分级 + 替代方案」这三件事同时做好。

### 1.3 非目标（明确不做）

- 不做酒类电商自营，只提供轻量跳转（聚合链接到京东/天猫/美团闪购）。
- 不做专业调酒教育（不加利口酒大全、蒸馏工艺等深度内容）。
- 不做 B 端（酒吧）市场。
- 不做社交陌生人匹配、不做直播。
- 不做 KTV/酒吧预订。
- 不覆盖白酒、黄酒、国产米酒的复杂细分（第一版聚焦烈酒家族 + 利口酒 + 果酒）。

## 2. 目标与可量化指标

### 2.1 北极星指标（North Star）

**每日完成一次「调酒制作」行为的独立用户数（Daily Active Makers, DAM）**

定义：当日内完成从「打开配方 → 确认材料 → 标记已完成」的完整链路（含点了「我做完了」按钮）的去重用户数。

理由：这个指标直接反映产品是否帮用户把「想调一杯」变成「真的调了一杯」。下载、注册、看配方都只是中间行为，只有真的调了，用户才会产生留存和社区内容。

### 2.2 过程指标

| 指标 | 定义 | 基线（假设） | 目标（P0 上线后 4 周） | 观测周期 |
|---|---|---|---|---|
| 注册转化率 | 访问首页 → 完成年龄确认并登录 | 30% [Assumption] | ≥ 55% | 周 |
| 库存录入完成率 | 登录后 → 录入 ≥ 1 件基酒 | 40% [Assumption] | ≥ 65% | 周 |
| 配方详情页 → 开始制作 转化率 | 看配方详情 → 点击「开调」 | 25% [Assumption] | ≥ 40% | 日 |
| 开始制作 → 完成制作 转化率 | 点击「开调」→ 标记完成 | 50% [Assumption] | ≥ 70% | 日 |
| 可制作配方点击率 | 首页「我能做的」tab 点击 | 60% [Assumption] | ≥ 75% | 日 |
| 社区 UGC 发布率 | 月 DAU 中发布过 ≥ 1 条调酒的比例 | 3% [Assumption] | ≥ 5% | 月 |
| 7 日留存 | 次日安装用户中第 7 日回访比例 | 15% [Assumption] | ≥ 25% | 周 |
| 举报有效率 | 举报中被审核判定为违规的比例 | - | 5%–15%（过高说明内容池脏，过低说明审核松） | 周 |

> 注：基线值为行业公开数据推断值，正式上线后以真实数据替换，再二次设定目标。

## 3. 范围与版本分期

### 3.1 MVP（P0，首版发布）

**一句话范围**：新手用户从「有一瓶基酒」到「第一次调出一杯能喝的酒」的完整闭环 + 轻量社区。

包含模块：

| 模块 | P0 包含 | P0 不包含 |
|---|---|---|
| 首页 | 搜索、筛选、推荐、「我能做的」库存反推、配方卡片 | 个性化推荐算法（P0 用规则引擎）、AI 换酒 |
| 酒库 | 已有酒类、已有材料、分类浏览、一键补货跳转、收藏配方 | 自动扫描识别酒瓶、扫码入库、库存保质期 |
| 酒圈 | 社区列表、点赞/踩、评论（文字）、举报 | 视频发布、私信、关注关系、话题标签 |
| 我的 | Apple ID 登录、年龄确认、基础设置、协议 | 多账号切换、头像挂件、成就系统 |
| 制作流程 | 配方详情 → 步骤指引 → 完成记录 | 计时器、拍照打卡自动生成 |

### 3.2 P1（上线后 8–12 周）

- 个性化推荐（基于点击、制作历史）
- 视频配方发布与播放
- 关注关系与消息通知
- 基酒扫码入库
- 缺料一键补货（聚合接口直通下单，而非只跳转）
- 调酒成就系统（连续 7 天打卡、首杯完成等）
- 配方收藏分组
- 首页「我能做的」配方来源标识（盏 · 精编 / DIY）+ 来源筛选 + 官方与 DIY 混合排序（HM-06）

### 3.3 P2（上线后 6 个月）

- AI 换酒：说一句「我有伏特加 + 橙汁」，自动生成可做列表
- 家庭调酒派对模式（多人加入、共同完成一杯）
- 线下活动入口（联名酒吧体验日）
- 海外版（英文版，适配 Difford's 规范）
- 会员制（专属配方包、无广告、线下福利）

## 4. 用户画像

### 4.1 核心画像

**画像 A：都市微醺新人（主力用户，占比 60%+）**

| 项 | 描述 |
|---|---|
| 年龄 | 22–32 岁 |
| 性别 | 女 55% / 男 45% |
| 城市 | 一线 + 新一线 |
| 职业 | 白领、互联网从业者、研究生 |
| 饮酒场景 | 下班后独饮、小范围朋友家聚会（4 人以内） |
| 当前行为 | 便利店买预调酒、偶尔去清吧；小红书收藏调酒教程但没动手过 |
| 核心痛点 | 不知道家里现有材料能调什么、怕比例错了难喝、买不到特定利口酒 |
| 成功标准 | 第一次调出来朋友说「好喝，你在哪学的」 |

**画像 B：独居宅男/宅女（次力用户，占比 25%）**

- 预算敏感，追求「便宜 + 有意思」
- 已有一瓶伏特加或朗姆，常年喝可乐桶
- 喜欢解锁隐藏配方、看 B 站教程
- 愿意为了「还不错的一杯」买 1–2 瓶新利口酒

**画像 C：夫妻/情侣二人组（传播节点，占比 15%）**

- 周末一起调一杯，拍照发朋友圈
- 口味偏好相反（一个爱甜一个爱烈）
- 会分享到社群、小红书，带来新注册

### 4.2 反画像（明确不服务）

- 专业调酒师（去用 Difford's 或专业论坛）
- 未成年（合规不允许）
- 只想喝预调酒、完全不想动手的用户
- 重度酗酒者（产品基调劝阻过量饮酒）

## 5. 核心用户故事与关键旅程

### 5.1 核心用户故事

1. 作为一个从没调过酒的新手，我想告诉我 App 里有伏特加、橙汁和柠檬，这样它能告诉我我能调什么。
2. 作为一个新手，我希望每个配方都有难度等级，让我知道从哪杯开始不容易翻车。
3. 作为一个缺材料的用户，我想在配方详情里直接看到「没有 XXX 可以用 YYY 代替」，而不是让我去买一瓶贵的利口酒。
4. 作为一个完成了调酒的用户，我想把我的成品照片发到社区，看别人的评论和点赞。
5. 作为一个家长，我不想让 18 岁以下的人用这个 App，也不想在社区里看到鼓励酗酒的内容。

### 5.2 关键用户旅程

---

#### 旅程 1：新手第一次调酒（P0 核心路径，必须跑通）

```
[首页] 首次打开 App
  → [年龄确认弹层] 选择生日 ≥ 18 岁
    → [登录弹层] Apple ID 一键登录
      → [首次引导 Step 1/2 · 选酒类] 按酒类家族勾选手头有的酒类（伏特加 / 朗姆酒 / 金酒 / 龙舌兰 / 威士忌 / 白兰地，多选）
        → [首次引导 Step 2/2 · 选酒款] 按已选酒类展示具体酒款（绝对伏特加 / 灰雁伏特加 / 斯米诺伏特加…），勾选 2–3 款或跳过
          → [首页 - 我能做的 tab] 看到 12 杯可做配方（包含 Screwdriver、Gin Tonic）
          → [配方详情 - Screwdriver] 看到难度 ★☆☆☆☆、步骤 3 步、替代方案
            → [制作流程页] 勾选 4 个步骤完成
              → [完成弹层] 「恭喜你调完了第一盏！」+ 一键发社区
                → [调酒记录] 存入我的「我的调酒」
```

关键指标：**首次登录 → 第一次完成调酒 的转化率**，P0 目标 ≥ 20%。

---

#### 旅程 2：缺料替代场景

```
[配方详情 - 新加坡司令]
  → 材料列表显示：金酒 ✓  柠檬汁 ✓  红石榴糖浆 ✗  苏打水 ✓
    → 红石榴糖浆 位置显示「缺料 · 可用 蔓越莓汁 替代」
      → 点击「蔓越莓汁」→ 查看替代说明（甜度偏高，建议减半）
        → 点击「一键补货」→ 跳转美团闪购搜索页（预设关键词「红石榴糖浆」）
          → 用户自行购买后回来标记「已到货」→ 配方自动解锁
```

#### 旅程 3：社区浏览与互动

```
[酒圈 tab]
  → 瀑布流浏览（图文为主，P0 不支持视频）
    → 点击一条「用户自制莫吉托」→ 帖子详情
      → 看到配方卡片（可直接点「我也调一杯」跳转配方）
        → 点赞 ✓  或 踩 ✗ （互斥）
          → 评论「看起来不错，我也试试」
            → 举报（如含酒精过量暗示、未成年出镜等）
```

---

#### 旅程 4：库存管理

```
[酒库 tab]
  → 「我的酒」列表（已有 3 瓶）
    → 点击「+ 添加」→ 搜索「梅酒」→ 选择规格 → 入库
      → 首页「我能做的」自动刷新，新增 5 杯可做
        → 点击「×」移除一瓶（搬家、喝完）
          → 首页「我能做的」对应配方剔除
```

---

#### 旅程 5：搜索与筛选

```
[首页搜索框]
  → 输入「酸的」→ 下拉联想：酸味 标签、Sour 家族配方
    → 或者点「筛选」→ 基酒=金酒 + 风味=清爽 + 难度=入门
      → 结果列表 8 条，按「匹配度」排序（有替代方案的排后面）
```

| 项 | 内容 |
|---|---|

## 8. 两套分类体系正式定义

### 8.1 酒的等级划分（针对「基酒 / 利口酒 / 果酒」等酒款本身）

**设计目标**：帮新手快速判断「我该先买哪瓶」，也作为配方难度的辅助维度。等级在首页卡片、配方详情、酒款详情上统一用**色条 + 文字**展示（如「入门酒」白底绿色条）。

#### 判定维度（4 维加权）

| 维度 | 权重 | 打分方式 |
|---|---|---|

| 获取门槛 | 25% | 电商/跨境能买到 = 5 分；需特定渠道 = 2 分 |
| 价格带（750ml） | 25% | ≤ 50 元 = 5 分；50–150 元 = 4 分；150–400 元 = 3 分；400+ 元 = 1–2 分 |
| 风味接受度 | 20% | 大众友好（无怪味）= 5 分；有鲜明特色 = 3 分；强个性（如苦艾酒）= 1 分 |

## 9. 业务规则

### 9.1 「我能做的」匹配逻辑

#### 匹配算法

```
可做配方 = 配方 R 满足：
  ① R 中 ≥ 80% 的材料 M 满足（M ∈ 用户库存） OR （M 有已录入的替代方案 A 且 A ∈ 用户库存）
  ② 不强制要求「装饰材料」（如柠檬片、薄荷叶、盐边，P0 标记为"可选装饰"不参与匹配）
  ③ 酒精类材料（基酒 + 利口酒）必须 ≥ 1 瓶，若配方为 mocktail 则无此要求

排序 = 匹配度 DESC → 剩余材料需要购买数 ASC → 配方热度 DESC
  匹配度 = (已有材料数 + 替代可用数) / 配方总材料数（不含装饰）
```

#### 降级展示规则

| 场景 | 展示 | 颜色 |
|---|---|---|
| 100% 材料已有 | 「可做 · 全材料齐」 | 绿色 ✓ |
| ≥ 80%，缺 1 样且有替代 | 「可做 · 用替代方案」 | 橙色 ⚠️ |
| ≥ 80%，缺 1 样无替代 | 「可做 · 还缺 1 样」 | 红色 ✗ + 补料按钮 |
| < 80% | 不出现在「我能做的」tab（避免用户点进来后全是红色） | - |

#### 替代材料规则

**预设替代库（P0 后台配置）**：

| 原材料 | 可替代 | 替换比例 | 风味影响 |
|---|---|---|---|
| 红石榴糖浆 | 蔓越莓汁 | 1:1 | 甜度偏高，建议减 20% |
| 橙皮利口酒（Cointreau） | 橙汁 + 少量糖 | 橙汁 2/3 + 糖 1/3 | 风味略淡 |
| 奶油利口酒 | 炼乳 | 1:1 | 偏甜，无巧克力味 |
| 新鲜柠檬 | 瓶装柠檬汁 | 1:1 | 香气略弱 |
| 新鲜薄荷叶 | 干薄荷茶包 | 1/3 量，提前泡 | 需提前浸泡 5 分钟 |
| 苏打水 | 气泡矿泉水 | 1:1 | 气泡略弱 |
| 君度（Cointreau） | 橙味利口酒任意 | 1:1 | 风味接近 |

替代关系不是对称的。后台维护一张 `ingredient_substitute` 表，支持多对多。

#### 来源标识、来源筛选与混合排序（P1）

**来源筛选**：筛选弹层第 ⑤ 项「来源」为单选项——`全部`（默认）/ `仅看官方精编` / `仅看 DIY`，与基酒家族、风味、酒精强度、难度四项**叠加生效**（AND 关系），命中数量实时回显在「确认」按钮上。切换 tab（推荐 / 我能做的）时来源筛选保留，不重置。

**列表混合排序规则**：在 9.1 匹配算法的排序基础上，第 3 顺位由「配方热度 DESC」替换为「来源分层 + 热度穿插」，规则如下：

| 顺位 | 规则 |
|---|---|
| 1 | 可做性档位：全材料齐 → 有替代 → 缺 1 样 |
| 2 | 匹配度 DESC |
| 3 | 官方精编与 DIY 混合：首条固定为官方精编；此后按「每 3 条官方精编插入 1 条 DIY」的比例穿插，避免 DIY 内容被官方内容完全淹没，也避免新手首页被未验证配方占满 |
| 4 | 同来源内部：官方按运营权重 + 热度 DESC；DIY 按社区热度（点赞 × 1.0 + 评论 × 1.5 + 踩 × −0.5）× 发布时间衰减 DESC，衰减参数沿用 9.4 |
| 5 | 剩余材料需购买数 ASC（仅官方组内生效，DIY 组不区分） |

**标识兜底规则**：

| 场景 | 展示与处理 |
|---|---|
| `source_type` 字段为空 / 历史脏数据 | 按「官方精编」兜底展示，筛选「仅看 DIY」时不计入 |
| DIY 配方来源帖子被删除 / 下架 | 卡片仍可展示但角标降级为灰色「DIY（已下架）」，不可点击；筛选仍计入 DIY |
| DIY 配方作者被封号 | 保留配方但角标置灰，点击进入帖子详情时展示「内容已不可用」占位 |
| 「仅看 DIY」无命中 | 空态文案「暂时没有你能做的 DIY 配方，去酒圈看看别人的作品？」+「切换到全部」按钮，不自动回退筛选 |
| 未登录 | 标识正常展示，来源筛选可用；点 DIY 角标可浏览帖子详情，互动动作弹登录引导 |

### 9.2 难度分级标准

| 档位 | 星星 | 判定规则 | 展示 |
|---|---|---|---|
| 入门 | ★☆☆☆☆ | ① 步骤 ≤ 3 步 ② 不需要专业工具（Shaker/Strainer） ③ 材料 ≤ 4 种 ④ 无"必须冷藏 8 小时"类前置准备 | 绿色标签 + 可配「新手推荐」角标 |
| 进阶 | ★★☆☆☆ | 满足以下任一：① 需要 Shaker 摇和 ② 步骤 4–6 步 ③ 材料 5–6 种 | 黄色标签 |
| 挑战 | ★★★☆☆ | 满足以下任一：① 需要明火或加热 ② 需要蛋清/奶油打发 ③ 需要提前浸渍/熬制糖浆 ④ 步骤 ≥ 7 步 | 红色标签 + 「需耐心」提示 |

> 难度是**配方本身属性**，不随用户变化。如果用户用替代材料简化了步骤，配方自身难度不变，但 UI 上可在材料清单里展示「按替代方案实际难度：入门」。

### 9.3 库存扣减与调酒记录

- 用户标记完成一杯后，**不自动扣减库存**（因为用户可能一瓶酒分 10 杯用，App 无法准确计算）。
- 调酒记录（`cocktail_record`）里**保存配方快照**（配方名、版本号、材料名、用量，当时的替代方案），防止配方后续调整导致历史回看错乱。
- 记录里标记：使用的是原配方还是替代方案。
- **手动标记完成**（不走制作流程页）：用户在配方详情页底部点「手动标记已完成」→ 记录同样写入，但 `cocktail_record` 里 `created_by_manual = true`，`steps_completed` 字段为空数组，快照里不含步骤勾选历史；手动标记和流程完成的记录在「我的调酒」里合并展示，区分标识仅作者自己可见。

### 9.4 点赞 / 踩与排序

- 点赞和踩**互斥**：点了赞 → 取消之前的踩；反之亦然。
- 同一用户对同一条帖子**只能二选一**，不可两边都点。
- 踩**不会**让帖子消失，只影响排序权重（降低热度公式里的点赞计数）。
- 社区排序公式：`热度 = 点赞数 × 1.0 + 评论数 × 1.5 + (踩数 × -0.5) + 发布时间衰减（24 小时内 × 1.2，48 小时内 × 1.0，72 小时 + × 0.7）`。
- 个人主页看自己发布的帖子，按「发布时间倒序」，不按热度。

### 9.5 评论规则

- 仅文字，≤ 200 字，iOS 系统键盘表情可输入。
- P0 **不支持**楼中楼，所有评论挂在帖子一级下。
- P0 **不支持**评论点赞、回复某人。
- 评论过机器审核（关键词过滤）后直接显示；命中敏感词 → 进入人工审核队列，临时隐藏。
- 帖子删除 → 评论一并删除，不可恢复。

### 9.6 内容审核与举报处理流程

```
UGC 发布
  → 机器审核（关键词 + 图片违规识别）
    → 通过：标记「待人工审核」，立即对发布者本人可见、他人不可见
    → 不通过：直接拒绝，返回「请修改后再试」+ 具体原因

人工审核（SLA ≤ 24 小时）
  → 通过：帖子正式公开
  → 拒绝：删除 + 通知发布者（站内信 P1；P0 用 toast）

用户举报
  → 前端临时隐藏（24 小时内发布者本人仍可见）
  → 进入审核队列，标注 priority = high
  → 审核员判定：
      ① 属实：删除 + 按违规等级处理
      ② 不属实：恢复展示
  → 举报人收到匿名结果通知（P0 暂不通知，P1 加）
```

**违规等级与处理**

| 等级 | 场景 | 处理 |
|---|---|---|
| 轻度 | 照片里酒精度数超过 40% 却配文「好喝又不醉人」暗示 | 删除 + 站内警告（累计 3 次禁言 7 天） |
| 中度 | 出现未成年出镜、鼓励拼酒、教自制烈酒 | 删除 + 禁言 7 天 |
| 重度 | 展示醉酒画面、鼓励酒驾、大量色情低俗 | 封号 |

### 9.7 未成年人与饮酒提示的合规规则

1. 首次打开 App **必须**先过年龄确认，不能跳过。
2. 未满 18 岁 → 展示劝退文案 + 跳转到 App Store 饮品分类，**不可关闭**。
3. 每条配方详情**固定**展示「适量饮酒 · 请勿酒后驾车」红色细条，不可关闭。
4. 每条酒圈 UGC 帖子**固定**展示同上提示。
5. 设置里「每次打开显示提示」开关默认开，用户可以关，但配方详情和帖子里的固定提示**不可关闭**。
6. App Store 年龄分级设为 **17+**。
7. 不做任何酒类促销广告、不提供购买链接以外的销售。

### 9.8 DIY 配方的署名与版权规则

**署名（强制）**

- 每条 DIY 配方在三个位置展示作者：首页卡片 DIY 角标旁的小头像（16×16）、配方详情页标题下方「@昵称 · 原创于 YYYY-MM-DD」、帖子详情页作者信息区。
- 署名信息始终取自配方的 `author_user_id`，不随昵称修改而丢失关联；昵称变更后展示新昵称，历史记录仍关联到同一用户。
- DIY 配方不可被「去署名」转载：站内任何二次引用（收藏、分享卡片、生成图片）都必须保留作者昵称与 `source_post_id` 回链。

**转载规则**

| 场景 | 规则 |
|---|---|
| 站内转载（用户把别人的 DIY 配方作为自己帖子的参考） | 必须在 DIY 贴士中注明「参考 @原作者」，系统在帖子配方卡上自动挂「转载」小标 |
| 跨平台搬运（把小红书/抖音内容整段搬进盏） | 视为违规，按 9.6 中度处理（删除 + 禁言 7 天），二次再犯按重度封号 |
| 官方精编引用用户原创 | 需运营在站内私信取得作者书面同意（站内信截图留档），转为官方后原帖保留，卡片改挂「盏 · 精编」，详情页保留「灵感来自 @昵称」一行 |

**抄袭判定与处理**

- 判定条件：材料构成 + 用量比例 + 步骤顺序三者综合相似度 ≥ 80%，且发布时间晚于原帖 ≥ 24 小时的，判定为抄袭。
- 处理：删除后发内容并保留原帖；被判定方收到原因说明；累计 2 次抄袭禁言 7 天，3 次封号。
- 反向误判：相似度 60%–80% 之间不直接删除，转人工复核，复核期内内容正常展示但标注「待核实」。
- 申诉：作者可在 7 日内通过举报通道「其他」提交申诉，审核员 48 小时内复核；复核结果需落库（`report.status`）。
- 配方被删除后，引用它的调酒记录不受影响（依赖 `recipe_snapshot`），首页「我能做的」次日刷新时剔除。

### 9.9 UGC 图片上传与展示规范

**适用范围（两类场景，规则不同，不可混用）**

| 场景 | 典型位置 | 展示规则 |
|---|---|---|
| 卡片主图 / 详情大图 | 酒圈瀑布流卡片（S1）、帖子详情主图（S2）、配方详情大图 | 按原始长宽比**等比缩放**，宽度满容器；不强制裁切，仅在超过 4:5（竖图）/ 4:3（横图）上限时按上限裁切 |
| 小尺寸列表缩略图（≤ 80px） | 我的调酒（M2，64×64 / 圆角 12px）、搜索结果行（H3）、酒库列表行（H1b / C2）、收藏列表行（C6，60×60 / 圆角 14px） | **固定尺寸** + `object-fit: cover` 居中裁切，不随原图长宽比变化；同一列表内所有缩略图尺寸与圆角必须完全一致（具体数值由组件规范定义），保证行高与右侧文字、日期、状态标签对齐 |

> 固定尺寸缩略图**不适用**下文第 1–2 条的等比缩放与比例上限规则；其源文件仍遵循第 4 条上传压缩与服务端两档出图要求。

**1. 展示原则（卡片主图 / 详情大图）**

- UGC 照片一律按**原始长宽比等比缩放**展示，宽度满容器（列表卡片内容宽 142px，左右各 14px 内边距），高度 = 宽度 ÷ 原图长宽比。
- **禁止拉伸变形，禁止强制方形（1:1）裁切**；列表页不得因比例不同而截断主体（酒液、杯型、手部动作等关键元素需完整可见）。
- 同一张图在列表页与详情页使用**同一比例规则**，不出现「列表是方形、详情是竖图」的错位。

**2. 比例上限（防超长图破坏版式）**

| 方向 | 原图处理 | 列表展示 | 超限处理 |
|---|---|---|---|
| 竖图 | 常见 1:1 / 4:5 / 3:4 原样等比展示 | 高度按原比例；上限 4:5（142 × 1.25 ≈ 177px） | 超过 4:5 的长截图/长图：按 4:5 **顶部对齐裁切**，右下角显示 20px 高的「长图」小标签 |
| 横图 | 常见 3:2 / 4:3 / 16:9 原样等比展示 | 高度按原比例；上限 4:3（142 × 0.75 ≈ 106px） | 超过 4:3 的宽幅图：按 4:3 居中裁切，不额外加标签 |
| 详情页主图 | 与列表同一原图 | 内容宽 350px，竖图上高 437px（4:5） | 超限沿用 4:5 顶部对齐裁切，标签文案为「长图 · 查看原图」，点击可查看未裁切原图 |

> 1:1 方图不再作为默认展示比例；仅在原图本身为 1:1 时按 1:1 展示。

**3. 文字块与卡片规格（不随图片比例变化）**

| 项 | 数值 |
|---|---|
| 图与文字间距 | 12px |
| 标题 | 最多 2 行，块高 36px（超出省略） |
| 作者行 | 20px |
| 互动行 | 18px |
| 文字块总高 | 90px |
| 卡片内边距 / 圆角 | 14px / 18px |
| 图片圆角 | 14px |

瀑布流允许左右两列因图片比例不同产生高度差；但**同一列内每张卡片的文字块必须等高（90px）**，不得出现文字被图片挤压、行高变形的情况。

**4. 上传端压缩与服务端出图**

| 环节 | 规则 |
|---|---|
| 客户端压缩 | 长边不超过 **1440px**；单张不超过 **5MB**；压缩时保留 **EXIF 方向信息**（不得因旋转信息丢失导致横竖颠倒）；上传前按压缩后体积校验，超限提示「图片过大，请重新选择」 |
| 服务端出图 | 原图入库后生成两档：① 列表缩略图（按容器宽度 @3x 输出，约 426px 宽，等比、不裁切主体）② 详情大图（约 1050px 宽，用于帖子详情与「查看原图」）；两档共用同一长宽比元数据 |
| 元数据 | 落库记录原图 `width / height / orientation`，列表与详情均按该比例渲染，避免前端二次猜测比例 |

**5. 原型对应**

- 列表：S1 酒圈瀑布流（横图 95px 高、竖图 177px 高 + 「长图」角标，文字块 90px 等高）。
- 详情：S2 帖子详情主图（350 × 437，4:5 顶部对齐，角标「长图 · 查看原图」）。
- 历史记录：M2 我的调酒缩略图（固定 64 × 64、圆角 12px、`cover` 居中裁切，所有行尺寸一致，不参与等比缩放）。

## 12. 合规与风险

### 12.1 风险表

| 风险 ID | 风险描述 | 概率 | 影响 | 应对方案 |
|---|---|---|---|---|
| RSK-01 | 未成年人绕过年龄限制 | 低 | 高（App Store 下架风险） | 年龄确认用强制流程 + 改系统时间后重开仍触发；App Store 设 17+；首次启动录时间戳，防「修改后再次确认」 |
| RSK-02 | UGC 内容出现鼓励酗酒、酒驾 | 中 | 高（法律风险 + App Store 下架） | 机器审核关键词库 + 人工审核 SLA 24h；每条帖子固定提示；举报通道直达审核队列 |
| RSK-03 | 电商跳转链接失效（美团闪购接口变更） | 中 | 低 | 用通用 H5 搜索跳转而非深度链接；P1 再评估直接对接；失效时展示「请手动前往对应 App 搜索」 |
| RSK-04 | App Store 对酒精类 App 审核升级 | 中 | 高 | 提前对照 Guideline 1.2（酒精相关）自查；确保不出现「饮酒是健康的」描述；提示文案用「适量饮酒」「请勿酒后驾车」 |
| RSK-05 | UGC 图片版权纠纷（用户发网图） | 中 | 中 | 用户协议里明确要求「原创或授权图片」；机器审核识别网络热门图做提示；举报通道支持版权投诉类型 |
| RSK-06 | 配方准确性问题（新手按配方调坏了来投诉） | 低 | 中 | 配方数据都由调酒师团队审核；详情页底部加「此配方为标准比例，可按个人口味调整」免责说明 |

### 12.2 电商导流的合规边界

- P0 **不嵌入**任何电商 SKU 的购买按钮，只做「跳转搜索页」的轻量导流。
- 跳转 URL 必须是第三方 App 的**搜索页**而非具体商品页，避免 App Store 判定为「代购」。
- 不接收电商的广告费或 CPS 分成（P0 阶段），避免商业误导。
- 跳转到的平台**固定为美团闪购搜索页**（渠道决策已拍板，单渠道、单按钮，不做渠道选择弹层）；跳转时预设关键词（如「红石榴糖浆」）。

## 15. 附录

### 15.1 术语表

| 术语 | 解释 |
|---|---|
| 基酒（Base Spirit） | 配方里含量最大的酒精成分，通常 40%+ ABV。8 大家族：金酒、伏特加、朗姆、龙舌兰、威士忌、白兰地、梅酒清酒、无基酒 |
| 利口酒（Liqueur） | 带甜或风味的低 ABV 酒，如 Kahlúa、Bails |
| 装饰材料（Garnish） | 柠檬片、薄荷叶、盐边等，不影响核心风味，P0 不参与匹配 |
| Mocktail | 不含酒精的「假酒」，P0 也支持（用无基酒分类） |
| 热度值（Heat Score） | 用于社区和配方排序的加权值，后台可配置参数 |
| DAM | Daily Active Makers，每日完成调酒的独立用户数，北极星指标 |
