# 盏 ZHAN · 家庭调酒 App — 初版设计交付

「盏」是一款面向家庭场景的调酒 App：用户录入手边的酒与配料形成「酒库」，App 据此推荐当下能做的配方，并提供分步制作引导、酒款/配料管理与社区分享。Slogan：**一盏好调酒，在家就能做**。

本仓库是**初版设计交付**，包含 PRD 正文、各版本静态视觉稿、一套可点击的前端演示稿，以及 3D 等级图标的设计方案。其中 **`icons-3d/v10` 为已定稿的「钻石」方案**，`icons-3d/v1`–`v6` 为历史迭代留档。全部为设计/演示用途，不含后端与真实业务逻辑。

## 如何打开

- 可运行前端稿：直接双击或拖进浏览器打开 `app/index.html`。左侧栏为页面导航，筛选弹层、配方跳转、评论等均为真实交互；页面内可跳转到 `app/levels/levels.html`。
- 等级方案页：单独打开 `app/levels/levels.html` 亦可，页内「回到可点击原型」链接指回 `app/index.html`。
- 静态稿：`mockups/*/index.html` 是对应版本的渲染页，双击即可在浏览器中打开；`mockups/*/*.png` 为逐帧截图，可直接看图。
- 3D 图标动效：打开 `icons-3d/v10/rotating-icons-v10.html`（定稿方案，可拖动旋转）；历史版本为 `icons-3d/v1`–`v5` 下的 `rotating-icons.html`。均内含内联 three.js，离线可运行。

> 无需 npm 安装、无需启动服务；`file://` 直接打开即可（`app/index.html` 也是双击可用）。

## 图片 / 动效的对照方式

- **静态稿 PNG 命名 = 页面编码**，前缀代表模块：
  - `H1`/`H1b` 首页推荐 / 可制作列表，`H2` 筛选弹层，`H3` 搜索结果
  - `C1`–`C6` 酒库（总览 / 酒款列表 / 添加 / 酒款详情 / 配料清单 / 收藏）
  - `G1`–`G3` 配方详情 / 制作流程 / 完成页
  - `S1`–`S4` 社区信息流 / 帖子详情 / 发布 / 举报弹层
  - `M1`–`M3` 我的 / 我的调酒 / 设置
  - `L1`–`L3b` 年龄确认 / 登录 / 首次引导（酒类 → 具体酒款）
- 文件名与渲染脚本中的 frame id 一一对应（`render.js` 末尾的 `window.__ZhanFrames__` 即截图顺序），`screenshot.js` 按该列表逐帧输出 PNG。
- **3D 图标版本目录内（`v1`–`v6`，历史迭代）**：
  - `L1.png`–`L5.png` 为大尺寸预览（设计评审用）
  - `L1@24.png`–`L5@24.png` 为 24px 实际使用尺寸的对照图（判断小尺寸可读性看这组）
  - `levels-overview.png` 为等级总览，`in-app-usage.png` 为在 App 内的实际排版示意
  - `compare-*.png` / `v4-vs-v5.png` / `palette-compare.png` 等为版本间对比图
  - 版本演进：v1 基础几何 → v2/v3 材质与配色探索 → v4 材质/透明度/调色板对比 → v5 细化与 v4 对比 → v6 背景适配矩阵（`bg-matrix.png`）

## 3D 等级图标：v10 定稿方案（钻石）

v10 是已定稿的等级图标方案：9 个代表配方各生成一枚钻石，交付 1024 与 24 两档透明 PNG，附旋转页。**v1–v6 均为历史迭代，只作过程留档，不作为交付口径。**

设计逻辑：

- **四维风味驱动不规则立体**。酸 / 甜 / 酒三轴（1–5）按比例映射到几何：甜度决定整体高宽比（1.34 → 1.05）、酸度决定冠高比（0.30 → 0.43）与台面收窄量、酒精度决定腰围偏心（−1 → +1）；第四维「复杂度」由三轴分散度反量推导，控制单刻面削面深度（0.06 → 0.22）。外形为 10 边环叠加双正弦扰动，扰动相位由风味组合决定，因此同一配方可稳定复现、不同配方不重复。
- **颜色只编码风味身份**：酸 → 青柠、甜 → 蜜琥珀、酒 → 姜红，在 LCH 空间按权重混合；强度由形状承担，颜色不承担强弱。
- **毛玻璃材质**：transmission 0.78 / roughness 0.3 / clearcoat 0.5，另有轻微色散，靠背后内容产生折射。

## 已知限制

1. `mockups/` 下全部是**静态截图**，不可点击；交互行为以 `app/` 可运行稿为准。
2. `app/` 是前端演示稿：数据硬编码在 `app.js`，刷新即重置；无后端、无账号体系。仅还原 `home / search / bottle / bottle-detail / recipe / flow / chat / comment / me` 9 个路由，PRD 中的设置、我的调酒等页面未做可运行实现，仅以静态 PNG 呈现。
3. PRD 中提出的电商（美团闪购单渠道）、UGC 发布、扫码入库等能力在原型里均未接入，只有界面表达。
4. 3D 图标历史版本（v2 / v3）的 `@24` 小尺寸在深色背景上对比度偏低，仅供过程参考，选型不要以此为准。
5. **v10 在 24px 下四维轮廓不可辨**：高宽比、冠高比、腰围偏心等差异在该尺寸被抹平，小尺寸实际只剩颜色与明度可区分，需配合文字标签使用。
6. **v10 在照片类底图上体色对比不足**：实测体色与背景的相对亮度比为 1.01–1.44（纯白 1.81–3.38、纸底 1.61–3.01、深色底 5.24–9.80），照片底需靠 7.1–8.3 的外描边兜底，不能只依赖体色分离。
7. **v10 的折射依赖底片内容**：毛玻璃/色散只有背后有可折射内容时才可见，纯色底上接近半透明色块。静态 PNG 无动画，立体感以 `rotating-icons-v10.html` 为准。
8. `icons-3d/v7` 的渲染产物尚未完成，本仓库未收录；`v10` 与其他版本的构建脚手架 `_src`（含 `node_modules`、临时渲染帧）亦未收录，因此不能从本仓库直接重跑渲染。
9. `mockups/*/screenshot.js` 中写死了原机器的 Chrome 路径与 puppeteer 依赖路径，直接复跑需先改路径并安装依赖。
10. `assets/` 内图片来自 Unsplash（见 `mockups/hifi/dl.sh` 中的原始链接），仅作设计演示，商用需另行授权。
11. PRD 内部分字段为占位（如作者栏、部分评审日期标 `[TBD]`）。
